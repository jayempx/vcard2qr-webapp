# vcard2qr-webapp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the approved public QR generator and code-protected shared workspace in a clean public repository, with verified Docker GitOps deployment.

**Architecture:** A single Django application serves templates, static assets, JSON operations and persistent destination pages. PostgreSQL stores QR records, rate-limit buckets and temporary batch state; static generation remains in memory. Portainer builds the exact source revision promoted after CI checks.

**Tech Stack:** Supported Django LTS, Python 3.14, PostgreSQL, qrcode/Pillow, openpyxl/defusedxml, Gunicorn, WhiteNoise, vanilla JavaScript; pinned and verified dependencies. Montserrat via Google Fonts initially, explicitly allowed by production CSP.

**Spec:** `docs/SPEC.md`

## Global Constraints

- UI in English; no company references, Privacy section, separate admin UI or public registration.
- Public generation includes 10 types; Excel requires unlock and supports vCard/website only.
- Six ASCII digits in ACCESS_CODE; automatic submit; 24-hour absolute session lifetime and secret rotation revocation.
- PostgreSQL, public random IDs, total opens and last-opened time only; never persist raw visitor IPs.
- Public history/CI must not expose secrets, personal data or actual infrastructure values. Use reserved example domains and GitHub noreply identity.
- New independent project: import no old Git history, data, deployment state or admin workflow.

## Review Focus

- Non-ASCII contact names, delimiter injection, long payloads and copied/transparent QR decodability (Task 1).
- Direct unauthorized API requests, CSRF, brute-force attempts, secret rotation and concurrent status changes (Task 2).
- Scanned stale/disabled links, XSS/unsafe URI schemes, counter races and download double-counting (Task 3).
- Malformed/expanded XLSX, formulas, missing leading zeros, cancellation and retry duplication (Task 5).
- Stale CI promotion, schema migration failure, volume permissions and restore retaining public IDs (Task 6).

## Task 1: Validated payload and QR engine

**Files:** `core/payloads.py`, `core/vcard.py`, `core/qr.py`, `tests/test_payloads.py`, `tests/test_qr.py`, `requirements.in`, `requirements.lock`, `pyproject.toml`.

**Interfaces:** `normalize_content(kind: str, data: dict) -> dict`; `build_payload(kind: str, data: dict) -> str`; `render_export(payload: str, appearance: dict, format: str) -> bytes`. Validation errors carry field keys and safe human-readable messages. Supported kind keys: `vcard`, `website`, `text`, `wifi`, `email`, `phone`, `sms`, `location`, `event`, `whatsapp`.

- [ ] Write failing tests for all ten payloads; reject javascript/file URLs, newline/header injection and invalid coordinates. Assert UTF-8 vCard folding and multiple unique custom properties.
- [ ] Implement payload serialization and QR geometry from scratch, including typed event timezone validation and Wi-Fi escaping. No code or tests from previous projects.
- [ ] Decode PNG and rasterized SVG with ZXing; assert payload equality, four-module quiet zone, minimum three pixels/module, contrast >=4.5:1 and transparent export. Reject overflow rather than producing a broken image.
- [ ] Pin dependencies, run core tests and lint, commit the isolated engine with noreply metadata.

## Task 2: Django foundation, shared code gate and private records

**Files:** `manage.py`, `config/settings.py`, `config/urls.py`, `config/wsgi.py`, `qrapp/models.py`, `qrapp/access.py`, `qrapp/views.py`, `qrapp/migrations/0001_initial.py`, `qrapp/tests/test_access.py`, `qrapp/tests/test_records.py`.

**Interfaces:** QRRecord holds random public ID, name, kind, normalized JSON data, appearance JSON, active, total_opens, last_opened_at, created_at and updated_at. No User dependency. JSON routes: `/api/unlock/`, `/api/lock/`, `/api/records/`, `/api/records/<id>/`, `/api/preview/`, `/api/export/`. Private mutations use POST/PATCH/DELETE and CSRF; public render/export use POST without saving content.

- [ ] Test private list/create/edit/toggle/delete/export denial without gate, including expired sessions and direct requests. Test wrong/leading-zero code, sixth-digit submission boundary, CSRF and revocation after ACCESS_CODE rotation.
- [ ] Configure strict production secrets, allowed hosts, trusted proxy only, secure signed cookies and absolute session expiry. Use constant-time code comparison and a server-secret-derived session version.
- [ ] Add database-backed rate limits: default five failed unlock attempts per HMAC-address bucket per 15 minutes plus global hourly protection; avoid IP in persistent logs. Reject oversized JSON and payloads before rendering.
- [ ] Implement list/search pagination and validated CRUD; partial status PATCH updates only active, avoiding stale form overwrites. Generate opaque stable identifiers and preserve counters on edits.
- [ ] Run PostgreSQL-backed tests, migration checks and `manage.py check --deploy` with synthetic settings; commit.

## Task 5: Bounded Excel workflow

**Files:** `qrapp/imports.py`, `qrapp/batch_views.py`, `qrapp/static/qrapp/imports.js`, `qrapp/models.py`, `qrapp/migrations/0002_batches.py`, `qrapp/tests/test_imports.py`.

**Interfaces:** Private `/api/imports/inspect/`, `/api/imports/validate/`, `/api/imports/<id>/step/`, `/api/imports/<id>/cancel/`, `/api/imports/<id>/download/`. Batch row processing is idempotent by batch ID + row index, guarded by transaction/row lock. Preserve completed results for 24 hours, never expose files publicly.

- [ ] Test malformed XML/ZIP and configured limits: 5 MiB compressed, 40 MiB expanded, 500 rows, 100 columns, 20 sheets. Test formulas/error cells, ambiguous mapping, numeric-phone warnings and text leading zeros.
- [ ] Implement sheet preview/mapping for vCard/website, validation report and explicit confirmation of valid rows. Static batches store only bounded temporary state, persistent batches create library records.
- [ ] Process short chunks with progress and cancellation; retry cannot duplicate persistent records. Keep completed results available after cancellation and expire access at 24 hours.
- [ ] Export row-numbered PNG or SVG files in ZIP with report; duplicate contact names cannot overwrite entries. Check code-gate and CSRF on all steps and downloads.
- [ ] Browser-run a mixed workbook, cancellation/retry and ZIP decoding; commit.
